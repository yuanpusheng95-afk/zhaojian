# 切片 2d：API 路由、签名 URL 与 SSE 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 2c 的 Agent 循环暴露给外部世界：`POST /projects/:id/messages` 入队轮次（幂等三态）、`GET /projects/:id/turns/:turnId` 轮次详情（候选图带 S3 签名 URL）、`POST .../selections` 手动选图、`GET .../events` SSE 流式推送轮次进展。结束时用户用 curl 即可走完「发消息 → 看进展 → 拿图 → 选图」全程。

**Architecture:** 维持 §3.1 的进程边界——API 进程**不加载 pi Agent**，只做三件事：写 `agent_turns`（走 2c 的队列）、读聚合视图（turn + generations + assets）、现签对象存储 URL。SSE 不碰 session 存储：它暴露轮次聚合进展；生成与选择会更新 generations/projects，不一定更新 turn 行，因此轮询的是聚合状态。原生 `node:http` 路由保持——六个路由 + 一个 SSE 端点不值得引入框架（决策 4 留了升级门）。

**Tech Stack:** 无新增依赖。`node:http` + `pg` + 既有 `@aws-sdk/s3-request-presigner`（`s3-asset-storage.mjs:75` 的 `getSignedUrl` 已就绪）、`node:test`。

**设计文档：** `docs/superpowers/specs/2026-08-20-pi-agent-migration-design.md` §3（进程边界）、§13（API 变更）、§7.5（幂等三态）、§12.3（配置与 stdout 纪律）

**前置：** 2a/2b/2c 已提交（`5c3f239`）。实测就绪的接线点：`createAgentTurnQueue.requestTurn`（三态：新建 `{turnId, replayed:false}` / 重放 `{turnId, replayed:true}` / `IdempotencyConflictError`/`ProjectBusyError`）、`getSignedUrl(key, {expiresInSeconds})`、`agent_turns` 表结构。

## 对设计文档的四点决策（实施前已核实）

1. **§13 的 `GET /generations/:id` 保留不删。** 它是调试入口，删除属于清债，不混进功能切片。README 标注 deprecated、仅供调试；继续返回既有 repository 形状，不补签名 URL，避免两套公开候选契约。
2. **SSE 暴露轮次聚合进展，不暴露 session 轨迹。** session `getLog` 是 Agent 轨迹流（每条工具调用、模型内部消息），公开它会扩大泄漏面；本切片只需要状态与候选产物变化。实现用短间隔轮询聚合查询，而不是只看 `agent_turns.updated_at`——生成和选择更新 `generations/projects`，不一定更新 turn 行。LISTEN/NOTIFY 留作优化位，MVP 不引入每连接专用 client。
3. **selections 直接交给 repository 原子裁决，不在 API 层预判幂等。** 先读 generation 再判断会产生 TOCTOU，且 `getGeneration(generationId)` 不校验项目归属。MVP 成功响应统一为 `200 { revisionId }`，重复同选天然幂等；失败透传 domain 错误。客户端只需要最终 revision，不需要区分新选/replay。若未来必须暴露 replayed，应让 `selectCandidate` 在事务内原子返回 `{ revision, replayed }`。
4. **不上框架（Fastify/Hono）。** 本切片 6 个 JSON 路由 + 1 个 SSE，原生 `node:http` 的 `routeRequest` 模式已在库中且带测试。之前讨论过"API 重写时落 Fastify 顺风车"——但 2d 的重写量比预想小（加 3 个路由、改 1 个），不足以摊销框架引入成本。**升级门**：鉴权中间件 + 限流 + 更多路由出现时迁移，届时 SSE 端点可平移。

## 接口契约

### `POST /projects/:id/messages`

```jsonc
// 请求体
{ "message": "把背景换成海边沙滩" }
// 头: Idempotency-Key: <key>（必需）
// 响应 202（新建）
{ "turnId": "turn_...", "replayed": false }
// 响应 200（幂等重放，同 key 同消息）
{ "turnId": "turn_...", "replayed": true }
// 409 IDEMPOTENCY_CONFLICT（同 key 不同消息）/ 409 PROJECT_BUSY / 404 / 400（空消息）
```

`Idempotency-Key` 缺失 → 400 `IDEMPOTENCY_KEY_REQUIRED`（在 API 层校验，不让队列的 TypeError 穿透成 500）。

### `GET /projects/:id/turns/:turnId`

§13 的返回体形状，按 2b/2c 落地现实校准：

```jsonc
{
  "turnId": "t_...",
  "projectId": "p_...",
  "status": "queued | running | completed | failed | aborted",
  "userMessage": "...",
  "error": { "code": "...", "message": "..." },        // 仅 failed/aborted
  "outcome": { "toolCalls": 3, "generations": 1, "selected": true },  // 2c 的 outcome_json 原样
  "generations": [
    {
      "generationId": "g_...",
      "status": "completed | failed",
      "patch": { "modify": [], "preserve": [] },
      "renderPrompt": "...",
      "selectedCandidateId": "c_... | null",
      "selectedRevisionId": "r_... | null",
      "candidate": {                                      // 仅 completed 且未越狱
        "id": "c_...",
        "assetId": "a_...",
        "url": "<签名 URL 或 null>",
        "urlError": "<仅候选 asset 缺失时出现>",
        "contentType": "<asset.metadata.contentType 或 null>"
      }
    }
  ],
  "createdAt": "...", "updatedAt": "..."
}
```

repository 的 candidate 实际形状是 `{ id, assetId, verification, createdAt }`；URI 在 assets 表。视图先按 `assetId` 读取 asset，再用 `resolveAssetStorageKey(asset.uri, configuredBucket)` 解析 key。只有候选 asset 本身缺失（`ASSET_NOT_FOUND`）才降级为 `"url": null` 并带 `urlError`；存储不可用、数据库故障、URI 畸形/异 bucket 都必须让请求失败为 500，避免把基础设施问题伪装成业务形状。`contentType` 来自 `asset.metadata.contentType`，缺失为 null。每个 generation 内嵌自己的 `selectedCandidateId` 和 `selectedRevisionId`；turn 顶层不设这两个字段，避免多代历史选择产生歧义。

### `POST /projects/:id/turns/:turnId/selections`

```jsonc
// 请求体
{ "generationId": "g_...", "candidateId": "c_..." }
// 200 → { "revisionId": "r_..." }
// 404 TURN_NOT_FOUND（turn 不属于该项目）；409 异选 / 跨项目 generation（CANDIDATE_SELECTION_ERROR）/ revision 冲突
```

先经 turnViews 校验 turn 归属（404——这是校验不是裁决，无 TOCTOU，也让路径里的 turnId 有真实语义），再调 `repository.selectCandidate({ projectId, generationId, candidateId })` 原子裁决。成功统一 200；重复同选由现有事务幂等返回原 revision；异选、candidate 不存在、revision 冲突分别透传对应 domain 错误。MVP 不返回 replayed。

### `GET /projects/:id/turns/:turnId/events`（SSE）

```text
event: turn          data: {完整轮次 JSON, 同 GET 详情形状}   // 连接后立即推当前快照;之后每次指纹变化推送; candidate.url 是短期签名 URL,不同事件可能不同
event: done          data: {}                                // 终态后发, 随即关连接
event: error         data: { code, message? }                 // 受控错误透传 code;未知错误固定 INTERNAL_ERROR 且不暴露原始 message
: ping                                                       // 每 15s 心跳注释行
```

查询参数：`?pollMs=1000`（下限 250ms 防滥用）。订阅时先查一次并立即推当前快照；终态接着推 done 后关闭。非终态进入轮询。多个客户端同时订阅时每连接独立轮询——MVP 接受（单用户产品）；LISTEN/NOTIFY 是将来的优化位。

### 错误码总表（mapError 增补）

| code | HTTP | 来源 |
|---|---|---|
| `IDEMPOTENCY_KEY_REQUIRED` | 400 | API 层 |
| `INVALID_SELECTION` | 400 | API 层(selections 请求体缺 generationId/candidateId) |
| `INVALID_MESSAGE` | 400 | API 层(message 空/非字符串;queue 的 TypeError 不让它变 500) |
| `IDEMPOTENCY_CONFLICT` | 409 | queue |
| `PROJECT_BUSY` | 409 | queue |
| `TURN_NOT_FOUND` | 404 | 已在 mapError ✓ |
| `REVISION_CONFLICT` | 409 | 已在 mapError ✓ |
| `CANDIDATE_SELECTION_ERROR` | 409 | 已在 ✓ |
